### 设计特点

1. **聚焦用户自我** —— 首屏是心理画像，而非岗位列表
2. **新/老用户分流** —— 弹窗欢迎 vs 完整体验
3. **专业可视化** —— ECharts 雷达图 + 进度条
4. **智能推荐** —— 仅 3-5 个高匹配岗位
5. **清晰流程** —— 大按钮导航（开始 → 评估 → 报告）

## 🔌 API 接口规范

### 四大核心 API

```bash
# 1. 获取心理画像 (Big Five)
GET /assessment/portrait/{candidate_id}
Response: [
  { name: "外向性", score: 8.5 },
  ...
]

# 2. 获取历史记录
GET /assessment/history/{candidate_id}
Response: [
  { id, job_title, match_score, created_at },
  ...
]

# 3. 获取推荐岗位
GET /assessment/recommended-jobs/{candidate_id}
Response: [
  { id, title, match_score, description },
  ...
]

# 4. 获取报告详情
GET /assessment/report/{record_id}
Response: {
  job_title,
  match_score,
  personality_trait: [...],
  match_analysis: { strengths, gaps },
  recommendations: [...]
}
```

**详见：** [BACKEND_API_SPECIFICATION.md](./BACKEND_API_SPECIFICATION.md)

## 📞 常见问题

### Q: 为什么 API 只有 4 个？
**A:** 这 4 个是核心 API，涵盖了首页所有数据需求。其他功能（文件上传、评估保存等）可另外设计。

### Q: 新用户第一次访问，推荐岗位怎么来？
**A:** 可返回热门岗位或随机岗位。等用户完成评估后，再基于心理画像推荐。

### Q: Mock 数据怎么切换成真实 API？
**A:** 修改 `request.ts` 中的 4 个 API 函数，调用真实端点而非 Mock。详见 [FRONTEND_MOCK_TEST_GUIDE.md](./FRONTEND_MOCK_TEST_GUIDE.md)。

### Q: 评估流程和首页的关系？
**A:** 评估在 `/immersive` 页面进行，完成后返回首页，首页重新加载数据并展示新的心理画像。

### Q: 可以修改首页设计吗？
**A:** 可以！所有样式都在 `<style scoped>` 中，修改不会影响其他组件。建议先看 [CANDIDATE_HOME_IMPLEMENTATION.md](./CANDIDATE_HOME_IMPLEMENTATION.md) 了解设计意图。
